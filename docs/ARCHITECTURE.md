# 네트워크 전투 설계

## 목표

클라이언트 화면에서 발생한 발사 결과를 곧바로 정답으로 사용하지 않습니다. 서버가 요청의 범위를 먼저 검사하고, 발사 시각의 충돌 상태를 복원해 명중 여부와 피해량을 결정합니다.

## 신뢰 경계

클라이언트가 전달하는 값은 다음 네 종류로 제한했습니다.

- 명중 대상으로 예측한 액터
- 총구 또는 추적 시작 위치
- 추적 끝 위치나 투사체 초기 속도
- 동기화된 서버 기준 발사 시각

피해량, 치명타 배율, 최대 요청 시간, 최대 사거리, 최대 투사체 속도, 최대 펠릿 개수는 서버가 가지고 있습니다. 클라이언트 요청이 범위를 벗어나면 리와인드 연산 전에 종료합니다.

## 서버 시간 동기화

1. 클라이언트가 로컬 시각 `t0`를 서버로 보냅니다.
2. 서버가 요청을 받은 서버 시각 `ts`를 반환합니다.
3. 클라이언트가 응답을 받은 로컬 시각 `t1`을 측정합니다.
4. 왕복 시간은 `t1 - t0`, 편도 지연은 왕복 시간의 절반으로 계산합니다.
5. 서버 현재 시각은 `ts + 편도 지연`으로 추정합니다.
6. 새 보정값은 기존 값에 `0.15` 비율로 반영합니다.

시간 동기화 패킷은 주기적으로 다시 보내므로 `Unreliable` RPC를 사용했습니다. 한 번 유실되어도 다음 측정으로 복구할 수 있기 때문입니다.

## 프레임 기록과 탐색

서버는 `TG_PostPhysics` 시점에 등록된 충돌 박스의 위치, 회전, 크기를 기록합니다. 최신 프레임은 이중 연결 리스트의 머리에 추가하고, 머리와 꼬리의 시간 차가 `1.25초`를 넘으면 오래된 프레임부터 제거합니다.

명중 시각이 두 기록 사이에 있으면 다음 순서로 보간합니다.

- 위치: 선형 보간
- 회전: 사원수 구면 선형 보간
- 충돌 박스 크기: 선형 보간

명중 시각이 기록 범위보다 오래됐거나 서버 현재보다 미래면 요청을 거부합니다.

## 판정 중 상태 복구

리와인드는 캐릭터의 실제 위치가 아니라 판정 전용 충돌 박스만 이동시킵니다.

1. 현재 충돌 박스 상태와 메시 충돌 모드를 저장합니다.
2. 보간한 과거 프레임을 적용합니다.
3. 캐릭터 메시 충돌을 잠시 끄고 전용 채널만 활성화합니다.
4. 무기 유형에 맞는 추적을 실행합니다.
5. 현재 프레임과 메시 충돌 모드를 복구합니다.

이 과정을 서버 내부에서 한 번에 처리해 다른 프레임까지 과거 충돌 상태가 남지 않게 했습니다.

## 무기별 처리

### 히트스캔

발사 시작점과 끝점 사이를 한 번 추적합니다. 맞은 충돌 박스가 치명 부위로 등록됐는지 확인해 피해량을 선택합니다.

### 투사체

발사 시작점과 초기 속도를 받아 `PredictProjectilePath`로 경로를 다시 계산합니다. 시뮬레이션 빈도는 `30 Hz`, 최대 속도는 `30,000 uu/s`로 제한했습니다.

### 샷건

최대 `16개`의 펠릿 끝점을 받습니다. 같은 과거 프레임에서 각 선분을 검사해 일반 부위와 치명 부위의 명중 수를 따로 집계한 뒤 서버 피해량을 곱합니다.
